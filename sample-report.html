Example: lost-response retry on a simulated paid API operation

Shows the structure of a potential bounded customer report. Every value on this page is made up solely to demonstrate formatting. No actual system was tested for this example.

1. Frozen question and boundaries

Question: Will the same logical paid API operation be executed more than once if the first response is lost and the client retries?
Environment: fictional single-process test fixture, no network, no payments, no third-party data.
Criterion: same operation identifier, unchanged arguments → exactly one simulated downstream execution.
Not in scope: worker restarts, cross-process coordination, real payments, on-chain settlement, production deployment.

2. Illustrative procedure

  1. Seed synthetic balance and construct a stable logical-action ID.
  2. Submit one authorized operation to the mock handler.
  3. Discard the simulated response before delivering it to the caller.
  4. Submit an identical retry and record decisions/effect count.

4. Evidence expected in a real engagement

  • Exact commands and parameters, with secret-bearing fields redacted.

5. Limitations and next steps

For a real system, an inconclusive outcome may require an additional scoped experiment. A process-local PASS cannot establish cross-worker idempotency, durable crash recovery, live settlement safety or general certification. Any code remediation would be separately scoped and priced.
